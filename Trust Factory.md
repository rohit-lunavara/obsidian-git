# References

> [!QUOTE] Original Capture
> “We’re accumulating code faster than we are accumulating trust.”
> 
> Code works or it doesn’t. One mistake in a long string of good decisions is the same as just a mistake. Trust accumulates slowly & evaporates in an instant. The difference is that in software sometimes you can repair the mistake in time proportional to the time it took to make the mistake. Trust is irreversible. Once gone it’s hard-to-impossible to get it back.
> 
> XP Practices - testing, pairing, CI, weekly planning, customer on the team, CD, refactoring and observability - build trust
> 
> XP Principles - humanity, mutual benefit, improvement, flow, redundancy - build trust
> 
> XP Values - communication, simplicity, feedback, courage, respect - build trust
> 
> Vibe coding vs trust
> 	1. AI cares about satisfying prompts, not purpose
> 	2. Encourages single player development
> 	3. Purely reactive project management - tactical progress but strategic failure
> 	4. AI ignores optionality and future change
> 
> Trust is not all that matters, but trustworthy behaviors which lead to trustworthy software result in trust - this is effective augmented development
> 
> What do we need to change to optimize for trust in the augmented development process? Slow down development:
> 	1. To ensure the code works
> 	2. To include structural improvements that expand options
> 	3. To encourage frequent person to person interaction
> 	4. To reinforce and update long term purpose
